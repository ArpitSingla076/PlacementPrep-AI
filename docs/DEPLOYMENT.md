# Deployment

Frontend on **Vercel** (static Vite build), API on **Render**, database on **MongoDB Atlas**.
**None of this was deployed or tested from the build environment.** `render.yaml`, `client/vercel.json` and the CI workflow are standard configurations written to be reviewed, not verified.

## 1. Atlas
1. Create a cluster, a database user, and allow your API host's egress IPs under *Network Access* (Render free instances have changing IPs; `0.0.0.0/0` is the usual compromise. Use a strong database password and a dedicated user if you do that).
2. Copy the connection string into `MONGODB_URI`.
3. Create the vector index: see [ATLAS_VECTOR_SEARCH.md](ATLAS_VECTOR_SEARCH.md).

## 2. API on Render
- Use `render.yaml` (Blueprint) or create a Node web service with root `server`, build `npm ci`, start `npm start`, health check `/api/health`.
- Set the secrets in the dashboard (`MONGODB_URI`, `GEMINI_API_KEY`, `LLM_MODEL`, `EMBEDDING_MODEL`, `EMBEDDING_DIMENSIONS`, `CLIENT_URL`). `JWT_SECRET` can be generated by Render.
- Free instances sleep when idle: the first request after a pause is slow, and in-memory quotas and rate limits reset on restart. Background document embedding is lost on a restart; the server marks such documents as failed on boot so they can be re-uploaded.
- Run `npm run ai:check:full` locally with the same key and model before going live.

## 3. Frontend on Vercel
Import the repo with root `client`, framework Vite. `client/vercel.json` rewrites all routes to `index.html` (single-page app). Then choose how the browser reaches the API:

| Option | How | Trade-offs |
|---|---|---|
| **A. Same site (recommended)** | Custom domains under one registrable domain, e.g. `app.example.com` (Vercel) and `api.example.com` (Render). `COOKIE_SAMESITE=lax`, `CLIENT_URL=https://app.example.com`, `VITE_API_URL=https://api.example.com/api` | Needs a domain. Cookies are first-party, so browser third-party-cookie blocking does not apply. |
| B. Cross-site | Default `*.vercel.app` and `*.onrender.com` domains. `COOKIE_SAMESITE=none` (cookie becomes `Secure`), `VITE_API_URL=https://<api>.onrender.com/api` | No domain needed, **but** browsers that block third-party cookies (Safari, increasingly Chrome) can break sign-in. |
| C. Vercel rewrite | Add `{ "source": "/api/:path*", "destination": "https://<api>.onrender.com/api/:path*" }` to `vercel.json`, leave `VITE_API_URL` empty, `COOKIE_SAMESITE=lax` | Same-origin for the browser. **Unverified:** the platform's proxy timeout may be shorter than a slow AI request (analysis can take up to about a minute). Check the current limits before choosing this. |

In every option `CLIENT_URL` must equal the frontend's exact origin: it drives CORS and the CSRF Origin check.

## 4. Checklist before sharing the URL
- [ ] `GET /api/health` returns `{"status":"ok"}`.
- [ ] Register, sign in, reload (session persists), sign out.
- [ ] `/api/ai/status` shows the model and embedding model as configured.
- [ ] Atlas index shows **ACTIVE**; upload a small PDF in Documents and ask a question.
- [ ] Read the Gemini API terms for your plan before real resumes or notes are used.
